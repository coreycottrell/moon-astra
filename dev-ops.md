## Project and baseline

The project directory is **`/home/corey/projects/moon-astra`**. This is a standalone browser game built from the Moon concept with new source and procedural machine models. It is independent of the earlier Moon projects. At handoff, this directory has no `.git` directory and no remote has been configured. ACG is to establish the repository.

The playable baseline includes a complete cube-sphere Moon, NASA LOLA elevation, a lunar color map, adaptive terrain tiles, global travel, five buildable machine types, resource production, recursive machine manufacturing, a simulated lunar mind, browser persistence, and desktop/phone controls. See `README.md` for gameplay and implementation boundaries.

The tested baseline passed 8 core checks, 3 browser scenarios, and a packaged-build smoke check. Evidence is in `artifacts/verification.md`, `artifacts/browser-results.json`, and the screenshots. These results describe the September 4 build; rerun the checks after implementation changes.

## Establish the Git repository

Run from the project itself, not from a parent project or an older Moon checkout:

```bash
cd /home/corey/projects/moon-astra
git init -b main
git add .gitignore README.md dev-ops.md NOTICE.md package.json package-lock.json index.html playwright.config.js src public scripts tests artifacts
git status --short
git diff --cached --stat

```

Review the staged files before the initial commit. The existing `.gitignore` excludes `node_modules/`, `dist/`, `test-results/`, `playwright-report/`, `.asset-cache/`, and artifact logs. The full backup deliberately includes those directories even though they do not belong in the source repository.

Keep `package-lock.json`, all of `public/data/`, `NOTICE.md`, and `public/data/sources.json` in the repository. The browser requires the prepared elevation and image assets; they are not generated by `npm run build`. Original downloads in `.asset-cache/` are useful for reproduction and belong in the backup rather than the initial Git commit. Keep credits when redistributing the game. Repository and remote names are for ACG to assign; no remote URL is assumed here.

## Dependencies and local operation

The baseline was built with **Node.js 24.13.1** and **npm 11.8.0** on Linux. Exact dependency versions are locked: Three.js 0.185.1, Vite 8.2.2, and Playwright 1.62.1. The application needs no API keys, account, database, or backend service.

```bash
cd /home/corey/projects/moon-astra
npm ci
npm run dev
```

Open **http://localhost:4173/**. Both `dev` and `preview` bind `0.0.0.0:4173` and use strict port selection. Run one at a time; stop the server in its owning terminal with Ctrl+C before switching. The server started during development is a session process, not an installed persistent service or scheduled job. Do not assume it survives a logout or reboot.

For the compiled application:

```bash
npm run build
npm run preview
```

`dist/` is the deployment directory. The backup includes a compiled build, but build it again after changing source or dependencies. On a different operating system or CPU architecture, use `npm ci` to replace the bundled Linux dependencies.

## Verification

```bash
npm test
npm run build
```

Start `npm run dev` in a separate terminal, then run:

```bash
npm run test:browser
node scripts/production-smoke.mjs
```

Browser scenarios use `http://127.0.0.1:4173/`. The production smoke helper starts its own loopback-only preview on **4174**, verifies `dist/`, then stops that preview. Its port must be free. Browser test contexts are isolated from the player's real browser profile.

The test runner and production smoke helper default to the Chromium executable already available on the original workstation:

```text
/home/corey/.cache/ms-playwright/chromium-1217/chrome-linux64/chrome
```

On another machine, install a compatible Chromium and set its path for both commands:

```bash
export MOON_CHROMIUM_PATH=/absolute/path/to/chromium
npm run test:browser
node scripts/production-smoke.mjs
```

The separate `scripts/inspect-browser.mjs` screenshot helper currently hardcodes the original workstation's Chromium path; adjust it if using that helper elsewhere. The headless verification scripts use software rendering and `--no-sandbox`; keep those helpers scoped to this trusted local application. Normal gameplay uses the player's ordinary browser and graphics driver.

## Assets and hosting

`public/data/` contains approximately 30 MB of compressed elevations, 2.6 MB of lunar imagery, a map preview, and source metadata. The first load fetches these files. Once served, gameplay does not call external APIs. The raw source downloads, hashes, transformations, and licenses are recorded in `public/data/sources.json` and `NOTICE.md`.

To regenerate assets, use Python 3 with NumPy and Pillow, then run `python3 scripts/prepare_assets.py`. It reuses files in `.asset-cache/` when present and downloads missing originals from the URLs in the script. Asset regeneration is optional for ordinary development because prepared assets are supplied.

Deploy **the contents of `dist/` at the web origin's root**. Asset URLs currently begin with `/data/`; hosting under a nested path needs a deliberate base-path change. Serve over HTTP(S), not by double-clicking `index.html` as a local file. Keep `/data/moon-height.u16.gz` intact. The loader supports both servers that deliver it as raw gzip bytes and servers that set `Content-Encoding: gzip` and let the browser decompress it. Avoid stale HTML pointing to assets from another build.

## Player saves

The save key is **`moon-astra-world-v1`** in browser local storage. Machines, geographic coordinates, resources, construction progress, and pause state persist there. Saves belong to the browser profile and origin: changing between `localhost`, `127.0.0.1`, a LAN address, or a new domain creates a different storage origin.

**The project ZIP does not include player saves from browser profiles.** Use the in-game field guide's **Export expedition save** button to preserve a played expedition separately. The current game has export but no import UI. Do not clear the existing save key during routine deployment. There is no offline production or multiplayer backend in this prototype.

## Full backup and restoration

Full snapshots are stored in **`/media/corey/Expansion/backups/moon-astra/`**, with timestamped names such as `moon-astra-full-YYYYMMDDTHHMMSSZ.zip`. Each ZIP contains a top-level `moon-astra/` directory including hidden files, prepared and original assets, installed dependencies, the compiled build, documentation, and verification artifacts. A matching `.sha256` file checks the ZIP; a `.manifest.json` describes the archived entries and their hashes.

Verify from the backup directory, substituting the actual timestamp:

```bash
sha256sum -c moon-astra-full-YYYYMMDDTHHMMSSZ.zip.sha256
unzip -t moon-astra-full-YYYYMMDDTHHMMSSZ.zip
```

Extract into a **new directory on the Linux filesystem**, then run `npm ci` and the verification commands. For example:

```bash
mkdir -p /home/corey/moon-restore-YYYYMMDDTHHMMSSZ
unzip /media/corey/Expansion/backups/moon-astra/moon-astra-full-YYYYMMDDTHHMMSSZ.zip -d /home/corey/moon-restore-YYYYMMDDTHHMMSSZ
cd /home/corey/moon-restore-YYYYMMDDTHHMMSSZ/moon-astra
npm ci
npm test
npm run build
```

The expansion drive is exFAT; the ZIP preserves Unix file modes and symlinks inside the archive. An extracted working copy should live on the normal Linux filesystem. Browser binaries outside the project and OS-level tools are not part of this project snapshot.
